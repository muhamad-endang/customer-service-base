# Knowledge Capture Protocol

## Trigger
Run whenever a task reveals new information from internal instruction, Developer response, Management decision, catalog, SOP, project document, corrected practice, recurring case, or legal/administrative source.

Ask:
"Would this help correctly handle another Webekspres client in a similar situation?"

If NO:
- keep it in the relevant case.

If YES:
- normalize into a reusable rule/explanation;
- check KB for duplicate/conflict;
- update an existing section when appropriate;
- preserve traceability where relevant;
- mark current guidance;
- add dated changelog entry.

## Living Filename
Keep `knowledge_base_webekspres_v0.008.md` until explicit version bump.

## Developer Forms
Developer form is both case evidence and candidate knowledge source. Only normalized reusable lessons enter global KB.

## Quality
Distinguish:
- official/current rule;
- older/legacy reference;
- project-specific example;
- unresolved conflict;
- information requiring validation.
